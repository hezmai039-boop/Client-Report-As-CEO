# لماذا يستغرق إضافة عميل واحد ومتابعته أكثر من ساعة؟ — تشخيص + خطة أتمتة كاملة

**التاريخ:** 06 أغسطس 2026
**النطاق:** منصة تقارير العملاء الآلية — شركة مساري لريادة الأعمال

---

## 1. التشخيص: أين يضيع الوقت فعلياً؟

بناءً على البنية الحالية للمنصة (Master Sheet + سجل فردي لكل عميل + Apps Script + Gemini AI)، عملية "إضافة عميل جديد" اليوم تمر بخطوات **يدوية متفرقة عبر أدوات مختلفة** (Drive، Sheets، Script Editor، Forms، Gmail)، وكل تبديل بين أداة وأخرى يكلّف وقتاً وتركيزاً. هذا هو مصدر الساعة الضائعة:

| # | الخطوة اليدوية الحالية | الوقت التقريبي | لماذا تُهدر وقتاً |
|---|---|---|---|
| 1 | البحث عن قالب سجل العميل في Drive ونسخه يدوياً | 10-15 دقيقة | لا يوجد زر واحد لإنشاء نسخة جاهزة بالأوراق الثلاث (البيانات اليومية / أرشيف التقارير / ملف العميل) |
| 2 | إعادة تسمية الملف وضبط صلاحيات المشاركة (Viewer/Editor) | 5 دقائق | يتم يدوياً لكل عميل، عرضة للنسيان (صلاحية خاطئة = تسريب بيانات أو فشل وصول) |
| 3 | نسخ معرّف السجل (Sheet ID) وإضافته يدوياً لصف جديد في **Master Sheet** | 5 دقائق | نسخ/لصق يدوي = عرضة لخطأ إملائي في المعرّف يوقف كل تقارير العميل لاحقاً |
| 4 | ربط/تهيئة نموذج Google Form لجمع بيانات هذا العميل تحديداً | 10-15 دقيقة | لا يوجد نموذج موحّد يوجّه تلقائياً حسب اسم العميل |
| 5 | فتح محرر Apps Script والتأكد يدوياً أن السكربت "يرى" العميل الجديد (فحص كود، أحياناً تعديل يدوي) | 10 دقائق | لا توجد آلية تسجيل تلقائي (auto-discovery) — كل عميل يحتاج تحققاً يدوياً من الكود |
| 6 | تشغيل تجريبي يدوي لدالة `generateAndSendReport` للتأكد من عدم وجود تقرير فارغ أو خطأ | 15-20 دقيقة | هذه هي الخطوة الأكثر استهلاكاً للوقت — تشمل: تشغيل الدالة، فتح الـ Logs، فحص البريد الوارد، وأحياناً تصحيح أخطاء (كما حدث فعلياً مع أول تشغيل لعميل "مطعم حاشي باشا") |
| 7 | متابعة يدوية لاحقة للتأكد أن بيانات العميل بدأت بالفعل (كما هو الحال الآن مع "وجهة مستثمر" التي لا تزال فارغة) | غير محدد | لا يوجد تنبيه تلقائي يخبرك "هذا العميل مسجَّل لكن لم يُدخل بيانات بعد" — يجب أن تتذكر وتتحقق بنفسك |

**الخلاصة:** المشكلة ليست في أي خطوة بمفردها، بل في **غياب مسار آلي واحد (single pipeline)** يربط هذه الخطوات السبع ببعضها. كل خطوة تعمل بشكل صحيح لكنها معزولة، فتتحول عملية بسيطة إلى جولة يدوية بين خمس شاشات مختلفة.

## 2. الحل: أتمتة كاملة بخطوة واحدة (Zero-Touch Onboarding)

الهدف: تحويل الخطوات السبع أعلاه إلى **استدعاء دالة واحدة** (أو نموذج تسجيل واحد) ينفّذ كل شيء تلقائياً خلال أقل من دقيقتين، بدون فتح أكثر من شاشة واحدة.

### 2.1 التصميم المقترح

```
نموذج "تسجيل عميل جديد" (Google Form)
        │  (الاسم، البريد، نوع التقرير: يومي/أسبوعي/شهري)
        ▼
onFormSubmit trigger → onboardNewClient_(name, email, periodType)
        │
        ├─ 1. ينسخ قالب السجل تلقائياً عبر DriveApp.copy()
        ├─ 2. يضبط الصلاحيات تلقائياً (share بالبريد المحدد كـ Editor محدود)
        ├─ 3. يضيف صفاً جديداً في Master Sheet تلقائياً (الاسم، البريد، Sheet ID، الحالة = "بانتظار أول بيانات")
        ├─ 4. يربط نموذج البيانات اليومية بالسجل الجديد تلقائياً (setDestination)
        ├─ 5. لا حاجة لتعديل كود Apps Script — يقرأ Master Sheet ديناميكياً في كل تشغيل
        ├─ 6. يشغّل فحصاً تجريبياً صامتاً (dry-run) للتأكد أن التوليد يعمل دون إرسال فعلي
        └─ 7. يرسل بريد تأكيد داخلي واحد لفريق مساري: "تم تفعيل [اسم العميل] بنجاح ✅ / أو: تحتاج مراجعة ⚠️"
```

### 2.2 مثال كود (`onboardNewClient_`) — يُضاف لملف الكود.gs

```javascript
/**
 * تسجيل عميل جديد بالكامل تلقائياً: نسخ السجل، الصلاحيات، التسجيل في
 * الجدول المركزي، وربط النموذج — كل ذلك من نداء واحد.
 */
function onboardNewClient_(clientName, clientEmail, periodType) {
  const templateId = getSetting_('CLIENT_TEMPLATE_SHEET_ID');
  const clientsFolderId = getSetting_('CLIENTS_FOLDER_ID');

  // 1) نسخ القالب داخل مجلد العملاء
  const templateFile = DriveApp.getFileById(templateId);
  const folder = DriveApp.getFolderById(clientsFolderId);
  const newFile = templateFile.makeCopy(`سجل - ${clientName}`, folder);
  const newSheetId = newFile.getId();

  // 2) صلاحيات: مساري Editor، العميل (إن رغبنا بإطلاعه) Viewer فقط
  newFile.addViewer(clientEmail);

  // 3) تسجيل الصف في Master Sheet تلقائياً
  const master = SpreadsheetApp.openById(getSetting_('MASTER_SHEET_ID'))
      .getSheetByName('العملاء');
  master.appendRow([
    clientName, clientEmail, newSheetId, periodType, 'بانتظار أول بيانات'
  ]);

  // 4) ربط نموذج البيانات اليومية بسجل العميل الجديد
  const form = FormApp.openById(getSetting_('DAILY_DATA_FORM_ID'));
  // يُستخدم نفس النموذج لكل العملاء مع حقل "اسم العميل" الذي يوجّه
  // السكربت لاحقاً للسجل الصحيح عبر البحث في Master Sheet — لا حاجة لنموذج منفصل لكل عميل.

  // 5) فحص تجريبي صامت (dry-run) بدون إرسال بريد فعلي
  const dryRunOk = testGenerateReport_(clientName, periodType, /*sendEmail=*/false);

  // 6) بريد تأكيد داخلي واحد لفريق مساري
  const status = dryRunOk ? 'تم التفعيل بنجاح ✅' : 'تحتاج مراجعة يدوية ⚠️';
  MailApp.sendEmail({
    to: getSetting_('INTERNAL_TEAM_EMAIL'),
    subject: `[أتمتة] تسجيل عميل جديد: ${clientName} — ${status}`,
    body: `تم إنشاء سجل العميل تلقائياً.\nSheet ID: ${newSheetId}\nالحالة: ${status}`
  });

  return { newSheetId, status };
}
```

> ملاحظة: `getSetting_`, `testGenerateReport_` دوال مساعدة يفترض وجودها أو إضافتها بنفس نمط الدوال الحالية (`getRowsForPeriod_`, `buildReportModel_`).

### 2.3 النتيجة المتوقعة

| المقياس | قبل الأتمتة | بعد الأتمتة |
|---|---|---|
| الوقت لإضافة عميل جديد | 60+ دقيقة | أقل من 2 دقيقة (تعبئة نموذج واحد) |
| عدد الشاشات/الأدوات المطلوبة | 5 (Drive, Sheets×2, Script Editor, Forms, Gmail) | 1 (نموذج تسجيل واحد) |
| احتمال خطأ بشري (معرّف خاطئ، صلاحية منسية) | مرتفع | شبه معدوم (كل شيء مبرمج) |
| المتابعة بعد الإضافة | يدوية، تُنسى أحياناً (كحالة "وجهة مستثمر") | تلقائية عبر بريد تأكيد + تنبيه لاحق إذا بقي السجل فارغاً بعد X أيام |
| التكلفة الإضافية | وقت موظف = تكلفة بشرية متكررة | صفر تكلفة تشغيلية إضافية (كل شيء ضمن حصة Google Apps Script المجانية) |

## 3. خطوة تكميلية: تنبيه تلقائي للعملاء "الفارغين"

لحل مشكلة عميل "وجهة مستثمر" (سجل فارغ منذ التسجيل) بشكل استباقي بدل الاكتشاف اليدوي، يُقترح إضافة **Trigger زمني يومي** يفحص كل عميل حالته "بانتظار أول بيانات" منذ أكثر من 3 أيام ويرسل تذكيراً تلقائياً (للعميل و/أو للفريق الداخلي)، بدل انتظار أن يلاحظ أحد الأمر يدوياً.

```javascript
function checkPendingClients_() {
  const master = SpreadsheetApp.openById(getSetting_('MASTER_SHEET_ID'))
      .getSheetByName('العملاء');
  const rows = master.getDataRange().getValues();
  rows.forEach(row => {
    const [name, email, sheetId, period, status] = row;
    if (status === 'بانتظار أول بيانات') {
      // إرسال تذكير تلقائي — بدل المتابعة اليدوية
      MailApp.sendEmail(email, `تذكير: لم نستلم بيانات ${name} بعد`,
        'يرجى تعبئة نموذج البيانات اليومية لبدء استلام تقاريرك تلقائياً.');
    }
  });
}
```

## 4. خطوات التنفيذ التالية (مقترحة)

1. إنشاء قالب سجل عميل موحّد نظيف (Template) ومجلد "العملاء" في Drive وحفظ معرّفاتهما في ورقة الإعدادات.
2. إنشاء نموذج Google Form واحد "تسجيل عميل جديد" (بدل التسجيل اليدوي في Master Sheet).
3. إضافة الدوال أعلاه إلى ملف الكود.gs الحالي وربطها بـ `onFormSubmit` trigger.
4. إضافة Trigger زمني يومي لـ `checkPendingClients_`.
5. اختبار حي: تسجيل عميل تجريبي والتأكد أن كامل المسار يعمل خلال دقيقتين فعلياً (وليس نظرياً)، تماماً كما تم التحقق سابقاً مع عميل "مطعم حاشي باشا".

---

**ملخص تنفيذي بجملة واحدة:** الساعة المفقودة اليوم هي كلفة التنقل اليدوي بين 5 أدوات لأداء عملية يمكن اختزالها بالكامل في نموذج واحد ودالة أتمتة واحدة — والتنفيذ لا يتطلب أي بنية تحتية جديدة، فقط ربط الأجزاء الموجودة فعلاً ببعضها.
