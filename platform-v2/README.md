# منصة تقارير العملاء الآلية — مساري (نسخة الألف عميل)

إعادة بناء كاملة لمنصة Google Apps Script الحالية على بنية حقيقية قابلة للتوسع:
**Node.js + TypeScript + PostgreSQL + Redis (BullMQ) + Gemini AI**

> **هذا المشروع مصمَّم ليُفتح في Windsurf ويُطوَّر منه مباشرة.**
> اقرأ قسم "مهام مقترحة لـ Windsurf" أدناه.

---

## لماذا أعيد البناء؟ (حدود المنصة القديمة)

| الحد في Apps Script | القيمة | الحل هنا |
|---|---|---|
| عدد المشغّلات Triggers | 20 فقط — يسقف "نموذج لكل عميل" عند ~14 عميلاً | لا مشغّل لكل عميل إطلاقاً: رابط `/f/<token>` فريد لكل عميل، ومورد التوسع الوحيد هو صفوف قاعدة البيانات |
| حصة البريد | 100/يوم (مجاني) | SMTP تجاري (SendGrid/SES/Mailgun) — عشرات الآلاف شهرياً |
| زمن التنفيذ | 6 دقائق للدفعة كلها | طابور BullMQ: كل تقرير مهمة مستقلة، معالجة متوازية، إعادة محاولة تلقائية |
| حارس التكرار | فحص يدوي بالكود | قيود `unique` في القاعدة — التكرار مستحيل بنيوياً (مشكلة "حاشي باشا ×3" لا يمكن أن تحدث) |
| خطأ اسم العميل | حدث فعلاً (نواف طه، 09-08-2026) | العميل لا يكتب اسمه أبداً — يُستنتج من رمز الرابط |

## الخريطة المعمارية

```
src/
├── server.ts            ← الخادم (Express): النماذج + API الإدارة + الحوكمة
├── config/env.ts        ← الإعدادات (تُقرأ من .env)
├── lib/
│   ├── db.ts            ← عميل Prisma
│   └── seed.ts          ← نقل عملائك الأربعة الحاليين كما هم
├── services/
│   ├── mailer.ts        ← البريد + قفل الاعتماد EXTERNAL_SEND_APPROVED
│   ├── ai.ts            ← توصيات Gemini (يحترم "تفضيلات التوصيات")
│   └── reports.ts       ← توليد التقرير (يقابل generateAndSendReport)
├── jobs/
│   ├── queue.ts         ← طابور BullMQ — قلب حل الألف عميل
│   ├── worker.ts        ← العامل: يعالج التقارير بتوازٍ + الجدولة
│   └── scheduler.ts     ← يومي 7ص / أسبوعي الأحد / شهري أول الشهر
└── routes/
    ├── publicForm.ts    ← نموذج العميل /f/<token> (بديل Google Forms)
    ├── clients.ts       ← API تسجيل وإدارة العملاء
    └── governance.ts    ← استبيان حوكمة مساري + سجل اطلاع الملاك
prisma/schema.prisma     ← قاعدة البيانات (تطابق أوراق Sheets حقلاً بحقل)
```

## التشغيل المحلي (5 خطوات)

```bash
docker compose up -d        # PostgreSQL + Redis
npm install
cp .env.example .env        # ثم عدّل القيم (على الأقل GEMINI_API_KEY)
npx prisma migrate dev      # إنشاء الجداول
npm run seed                # نقل عملائك الأربعة الحاليين
npm run dev                 # الخادم — نافذة أولى
npm run worker              # عامل التقارير — نافذة ثانية
```

ثم افتح: `http://localhost:3000` (خريطة النقاط) — `http://localhost:3000/governance` (استبيان الحوكمة)

## 🔒 قفل الاعتماد — منقول من النظام القديم كما هو

`EXTERNAL_SEND_APPROVED=false` في `.env` يعني: **أي بريد لعميل يتحوّل
إلى بريدك أنت** بعنوان "[معلَّق بانتظار الاعتماد]" — لا يصل أحداً غيرك
حتى تغيّرها بنفسك إلى `true`. أبقِها `false` طوال التطوير.

## مهام مقترحة لـ Windsurf (بالترتيب)

1. **تشغيل وتثبيت**: نفّذ خطوات التشغيل أعلاه وأصلح أي خطأ أنواع
   (types) يظهر — الكود كُتب بلا تشغيل فعلي للحزم.
2. **لوحة إدارة ويب**: صفحة HTML/React على `/admin` تعرض ما يعيده
   `GET /api/clients` (حالة كل عميل، آخر بيانات، آخر تقرير) بدل JSON.
3. **مصادقة**: حماية `/api/*` و`/governance*` بكلمة مرور أو جلسة —
   حالياً كل شيء مفتوح محلياً.
4. **PDF**: توليد التقرير كملف PDF مرفق (puppeteer أو pdfkit) بدل
   HTML في جسم البريد — لمطابقة النظام القديم الذي كان يرسل PDF.
5. **استيراد تاريخي**: سكربت يقرأ ملفات CSV مصدَّرة من سجلات Google
   Sheets القديمة ويحقنها في `DailyEntry` — للحفاظ على التاريخ.
6. **اختبارات**: vitest للخدمات الحرجة (mailer lock، حارس التكرار،
   periodRange).

## العلاقة مع النظام القديم

النظام القديم (Apps Script + Sheets) **يبقى يعمل كما هو** لعملائك
الحاليين حتى تكتمل هذه المنصة وتُختبر — لا إيقاف ولا ترحيل قبل
اعتماد صريح منك. الكود القديم موثَّق في نفس مستودع GitHub
(`apps-script/automation.gs`).
